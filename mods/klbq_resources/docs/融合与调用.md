# 融合与调用

运行版本 0.1.0；查询 API 版本 1。例子只供以后接入代码，不会在本包中自动执行或产生资源。

跨模组查询应放在 `AddSimPostInit` 或实体/玩法回调中，等各模组完成加载后再 `require`，避免依赖模组加载顺序。合并到同一宿主后的注册调用可直接放在该宿主入口。

## 查询

```lua
local Resources = require("klbq_resources/api")
local prefab = Resources.GetPrefab("stringsea_beacon")
-- "klbq_resource_stringsea_beacon"
local definition = Resources.GetDefinition(prefab)
-- definition.key / prefab / name / inspect / category
local is_resource = Resources.IsResource(existing_item)
```

`GetDefinition`、`GetPrefab` 接受短键或完整 Prefab ID，未知/无效输入返回 `nil`。`IsResource` 接受完整 ID 或实体，未知对象返回 `false`，不只凭标签认定资源。目录条目共享，调用方只读使用。

没有生成、扣除、兑换或抽卡 API。未来玩法由其自身在服务器端操作原生物品数量，不在客户端改权威状态。

### 短键

- 货币：`bablo_crystal`、`base_string`、`ideal_coin`。
- 凭证：`memory_sequence`、`redirect_sequence`、`stringsea_beacon`、`initial_sequence`、`resonance_sequence`。
- 外观材料：`topology_ring`、`tracing_plate`。
- 模式资源：`card_fragment`、`dice`。
- 终端：`terminal_michelle`、`terminal_xinghui`、`terminal_ming`、`terminal_qiandai`、`terminal_xi`、`terminal_kanami`、`terminal_flavia`、`terminal_eika`。

运行真值是 `scripts/klbq_resources/catalog.lua`；`docs/resource-catalog.json` 是设计比对数据，单元检查校对两者。

这是开发查看方式，不是正式来源设计。默认每组 40；收纳、保存和数量使用原生组件，没有账号绑定或死亡保留。

## 合并步骤

本轮未修改香奈美。以后获准合并时：

1. 复制 `scripts/klbq_resources/` 和 `scripts/prefabs/klbq_resources.lua` 到主模组同路径。
2. 复制 `anim/klbq_resources_items.zip`、`images/klbq_resources_items.xml`、`images/klbq_resources_items.tex`。
3. 在主模组入口加入：

```lua
require("klbq_resources/register").Install(env)
```

4. 保留主模组原有列表。安装函数追加 `PrefabFiles`、`Assets` 和资源字符串，不替换整张表。
5. 保留全部 20 个 `klbq_resource_` ID、图片元素名及动画名；不替换现有 `klbq_crystal`。
6. 继续使用 DST 两端必装；合并后关闭独立包，只保留一个运行所有者，并完整重启。
7. 在备份的独立世界验证旧物品、地面/容器/背包、重连与洞穴切换，再迁移正式使用。

同一 Lua 进程中，本版通过 `KLBQ_RESOURCES_OWNER` 保护同版重复注册；已加载目录与所有者版本冲突时明确报错。

DST 共享 `require` 缓存，因此这不是支持任意不同版本副本并存或热更新的保证。融合时同步同版代码并只启用一个所有者；跨版本共存应另做版本化入口，不随意清理游戏模块缓存。

## 文件职责

- `catalog.lua`：稳定身份、中文名称、类别、检查文本、40 个堆叠上限和共同资源路径。
- `api.lua`：查定义、查 Prefab、识别资源；加载时不依赖游戏对象。
- `register.lua`：追加资源与字符串、登记图集和同版唯一所有者。
- `prefabs/klbq_resources.lua`：统一联网物品工厂，两端共通结构先建，`SetPristine()` 后客户端返回，服务器添加原生物品/堆叠组件。
- `art/`、`tools/`、`tests/`、`docs/`：开发资料，排除于运行 ZIP。
